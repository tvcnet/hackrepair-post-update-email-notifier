# 1.6.0

## New
- Site-wide default for the per-post checkbox: editors opt in for each update (default, unchanged) or opt out.
- Notify on first publish (including scheduled posts) and later updates, or on updates only.
- Per-post cooldown (off, 5, 15 or 60 minutes) to prevent bursts from repeated saves.
- Background sending: in Automatic mode, lists above 20 recipients are sent in WP-Cron batches; the log shows progress.
- `[change_summary]`, `[revision_url]`, `[previous_title]` and `[event]` placeholders.
- Preview the email without sending, and live recipient counts in Settings and in both editors.
- Site Health checks, `wp pue` WP-CLI commands, personal data export/erasure for the log, a translation template and a daily bulk-test cap.

## Fixed
- A failed update check named “Disable Other Plugin Notices”; View Details showed the installed version when an update was available.
- Developer filters now receive the real `$post_before` (previously always null).
- Skipped updates no longer trigger the delivery-failure notice; each failure is logged once, with its error.
- Branding and Email Identity save without JavaScript; actions redirect after POST so reloading cannot resend a test.
- An opted-in update that cannot be sent is logged with its reason instead of silently consuming the choice.
- The optional plain-text part reaches every recipient and never unrelated email.
- Never-saved branding now uses the defaults shown on the settings screen (“[site_name] Notification” / “Thank you for supporting [site_name]”).

## Upgrade notes
- Installed folder, entrypoint, settings keys, meta key and hooks are unchanged. Developer filters that assumed a null `$post_before` should handle a `WP_Post`.
- After each processed update the per-post flag is removed rather than stored as “skip”, so the site default applies. Posts saved by earlier versions keep their stored flag until their next update.

Verified on Zendogs (WordPress 7.1 / PHP 8.2) with Mailpit and a real-WordPress integration script; see PROJECT.md for scope.
